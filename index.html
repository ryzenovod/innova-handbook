Инженерный справочник внедренца ЛИС

Практическое руководство для инженера отдела внедрения InnovaSystem: глубокое погружение в архитектуру, физическое подключение анализаторов, разбор сессий ASTM/HL7, рабочие T-SQL скрипты и готовые алгоритмы устранения аварий на объектах.

1. Архитектура ЛИС (Deep Dive)

Лабораторная информационная система (ЛИС) автоматизирует весь контур клинико-диагностической лаборатории (КДЛ). Архитектура состоит из 5 ключевых уровней, взаимодействующих через базу данных MS SQL Server и сетевые сокеты.

1. СУБД MS SQL Server

Роль: Центральное ядро состояния. Хранит заявки (Application), биоматериалы/пробы (Specimen), тесты и нормы (TestParam), результаты анализов (AnalysisResult) и историю аудита.

Важно для инженера: Любые блокировки в таблицах немедленно парализуют работу лаборатории. Обязательно уметь анализировать активные транзакции.

2. Сервер Драйверов (СД)

Роль: Мост между железом и базой данных. Работает как служба Windows. Опрашивает физические порты, распознает фреймы приборов, преобразует коды тестов через маппинг и записывает результаты в БД.

Стек: C#, .NET 8 (новые драйверы), C++ / COM (старые драйверы), Serilog для ротации логов.

3. Сервер Отчетов (СО)

Роль: Формирование печатных бланков с электронной подписью, штрихкодов пробирок и отправка PDF в архив или на почту.

Стек: FastReport (.fr3 шаблоны) в классической версии; в новой версии — микросервисы !RS_Backend, !RS_PrintingService и Blazor на порту 5173.

4. Обменная служба (MisExchange)

Роль: Автоматический прием направлений на анализы из поликлиники и передача готовых результатов обратно в электронную медицинскую карту (ЭМК).

Протоколы: HL7 v2 (ORM^O01 / ORU^R01), XML обмен через сетевые папки или веб-сервисы SOAP/REST.

2. Золотые правила внедренца

⚠️ 1. Правило «Красного Справочника» (Red Dictionary Rule)
Когда в клиенте ЛИС справочник тестов, норм или услуг подсвечен красным — это значит, что другой пользователь или зависшая сессия держит блокировку, либо локальный кэш устарел.
Что делать: Всегда нажимай «Обновить», а лучше полностью перезапусти клиент ЛИС перед редактированием! Если попытаться сохранить изменения поверх — ты затрешь настройки или заблокируешь таблицу для других врачей.
⛔ 2. Техника безопасности медицинского оборудования
  • Тумблеры питания приборов не трогать: Включать и выключать анализатор имеет право только штатный лаборант/инженер ЛПУ. Прибор может находиться в цикле промывки или калибровки стоимостью в сотни тысяч рублей.
  • Никакого «горячего» подключения COM-портов: Все интерфейсные кабели RS-232 / DB9 вставляются и выкручиваются только при выключенном питании прибора и ПК. Разность потенциалов между землей ПК и прибора сжигает микросхему MAX232 мгновенно!
🛡️ 3. Железный регламент работы на сервере
  • Перед любым изменением — полный бэкап: Команда BACKUP DATABASE LIMS TO DISK = '...' обязательна перед обновлением скриптов, установкой патчей или правкой конфигурации.
  • Все утилиты — только «От имени Администратора»: Драйверы, утилиты COM-портов и конфигураторы служб требуют повышенных привилегий для доступа к сокетам и реестру.
  • Согласование обновлений: На боевой базе обновления накатываются исключительно в согласованное технологическое окно с ответственным от заказчика.

4. SQL-Шпаргалка для инженера (MS SQL Server)

Эти проверенные T-SQL запросы решают 90% оперативных проблем с базой данных в КДЛ:

1. Проверка активных блокировок и зависших транзакций

Если система «зависла» и пользователи жалуются на бесконечное сохранение:

-- 1. Посмотреть все активные процессы и кто кого блокирует (колонка BlkBy) EXEC sp_who2 'active'; -- 2. Детальный запрос: кто держит блокировку и какой SQL выполняет SELECT blocking_session_id AS [Заблокирован кем (SPID)], session_id AS [Ждущий SPID], wait_type, wait_time / 1000 AS [Время ожидания (сек)], wait_resource, SUBSTRING(qt.text, (qs.statement_start_offset/2)+1, ((CASE qs.statement_end_offset WHEN -1 THEN DATALENGTH(qt.text) ELSE qs.statement_end_offset END - qs.statement_start_offset)/2) + 1) AS [Выполняемый SQL] FROM sys.dm_exec_requests qs CROSS APPLY sys.dm_exec_sql_text(qs.sql_handle) qt WHERE blocking_session_id <> 0; -- 3. Если блокирующий SPID завис (например SPID 65): -- KILL 65;

2. Поиск пробы и заказа по штрихкоду

Быстро найти, пришел ли заказ из МИС и в каком статусе находится пробирка:

DECLARE @Barcode NVARCHAR(50) = '1002345'; -- Штрихкод пробирки SELECT s.id AS [SpecimenID], s.number AS [Штрихкод], s.status AS [СтатусПробы], a.number AS [НомерЗаявки], p.lastName + ' ' + p.firstName AS [Пациент], t.name AS [НазваниеТеста], r.value AS [РезультатТеста], r.state AS [СтатусРезультата] FROM Specimen s JOIN Application a ON s.ApplicationId = a.id LEFT JOIN Patient p ON a.PatientId = p.id LEFT JOIN AnalysisResult r ON r.SpecimenId = s.id LEFT JOIN Test t ON r.TestId = t.id WHERE s.number = @Barcode;

3. Снятие блокировки красного справочника

-- Проверка зависшей блокировки редактирования в служебной таблице сессий SELECT * FROM SystemLock WHERE TableName LIKE '%Dictionary%'; -- Очистка зависшей блокировки (после подтверждения, что сессия закрыта) -- DELETE FROM SystemLock WHERE TableName LIKE '%Dictionary%' AND UserId = 129;

Популярные анализаторы: Справочник параметров связи

Sysmex XN-350 / XN-550 / XN-1000

  • Интерфейс: TCP/IP (Ethernet RJ-45) или RS-232.
  • Протокол: ASTM 1394-97 (High-level) поверх ASTM 1381 (Low-level).
  • Порт по умолчанию: TCP 5100 (или порт, заданный в меню IP-Communication).
  • Режим обмена: Двусторонний со штрихкодом (Bidirectional Host Query). Прибор считывает штрихкод → шлет запрос Q|... → ЛИС отвечает заказом O|... с тестами → прибор делает анализ и шлет R|....

Roche Cobas 6000 / c311 / e411

  • Интерфейс: RS-232 через Moxa NPort (режим Real COM).
  • Параметры COM: Скорость 9600 или 19200, 8 бит данных, четность None (N), 1 стоп-бит, аппаратный контроль потока отключен (None).
  • Протокол: ASTM или HL7. Строгие таймауты: если драйвер не ответил <ACK> в течение 15 секунд, прибор разрывает сессию с ошибкой интерфейса.

Mindray BC-5300 / BS-200 / CL-8000

  • Интерфейс: TCP/IP или RS-232.
  • Протокол: HL7 v2.3.1 (фреймы начинаются с 0x0B <VT> и заканчиваются 0x1C 0x0D <FS><CR>).
  • Особенность: Требует подтверждения сообщения пакетом MSA|AA|....

bioMérieux Vitek 2 / Vitek MS

  • Интерфейс: Сетевая папка (File exchange / BCI) или двусторонний ASTM драйвер.
  • Специфика: Микробиологические результаты содержат дерево: Микроорганизм → Антибиотики → МПК (MIC) → Экспертная оценка (S - Чувствителен, I - Промежуточный, R - Резистентный).

6. Файлы маппинга (VMOM.xml и .test.map)

Файл маппинга лежит в папке драйвера Mapping/ и сообщает системе, как интерпретировать данные с прибора.

📐 Жесткое правило очередности тегов в XML
Парсер драйвера требует строгого порядка тегов! Сначала всегда идут теги <Test>, затем <SkipTests>, затем <AllowTests>:
<?xml version="1.0" encoding="UTF-8"?> <VMOM version="1.0" description="Value Mapping Object Model"> <Model> <!-- 1. Описание тестов, коэффициентов и замен --> <Test Name="HGB" K="10.0"></Test> <!-- Пересчет г/дл в г/л --> <Test Name="GLU" K="1.0"></Test> <Test Name="HBsAg"> <Value DeviceValue="POS" LISValue="Положительно" /> <Value DeviceValue="NEG" LISValue="Отрицательно" /> <Value DeviceValue="&lt;0.05" LISValue="Менее 0.05" /> <!-- Экранирование < --> </Test> <!-- 2. Список исключаемых тестов --> <SkipTests> <TestRef Code="TEMP_TEST"/> </SkipTests> <!-- 3. Список строго разрешенных тестов (если нужен вайтлист) --> <AllowTests> <TestRef Code="HGB"/> <TestRef Code="GLU"/> <TestRef Code="HBsAg"/> </AllowTests> </Model> </VMOM>

7. Разбор логов анализатора (ASTM / HL7)

Лог драйвера пишется по умолчанию в C:\temp\LISClient.exe-[Драйвер]-YYYYMMDD.txt.

Обозначение направлений в логе:

  • >> — Прибор передает данные на ПК (Входящий поток).
  • << — Сервер Драйверов передает ответ на прибор (Исходящий поток).

Пример идеальной сессии передачи результата (ASTM):

14:10:01.100> >> <ENQ> (Прибор: "Есть данные!") 14:10:01.120> << <ACK> (Драйвер: "Слушаю, шли") 14:10:01.200> >> <STX>1H|\^&|||LIS||||||||1394-97<CR><ETX>A4<CR><LF> (Заголовок) 14:10:01.220> << <ACK> 14:10:01.300> >> <STX>2P|1||||Иванов^Иван||19850101|M<CR><ETX>B2<CR><LF> (Пациент) 14:10:01.320> << <ACK> 14:10:01.400> >> <STX>3O|1|1002345||^^^GLU|||20261026<CR><ETX>8F<CR><LF> (Штрихкод 1002345) 14:10:01.420> << <ACK> 14:10:01.500> >> <STX>4R|1|^^^GLU|5.4|mmol/L|3.9-6.1|N||F<CR><ETX>1C<CR><LF> (Глюкоза = 5.4) 14:10:01.520> << <ACK> 14:10:01.600> >> <STX>5L|1|N<CR><ETX>03<CR><LF> (Конец сообщения) 14:10:01.620> << <ACK> 14:10:01.700> >> <EOT> (Сессия завершена успешно)

8. Пошаговая диагностика аварий (Field Troubleshooting)

1
Симптом: Анализатор прогнал пробу, но в ЛИС результатов нет

Пошаговый алгоритм проверки:

  1. Проверь физику и Moxa NPort: Пингуется ли IP Moxa? Горит ли индикатор Link/Ready? Открой веб-интерфейс Moxa → Monitor → Line status (должен быть статус Open / Listening, счетчик Rx/Tx должен расти).
  2. Проверь службу Windows: Запусти консоль от админа: sc query "LimsDriverServer". Если остановлена — net start "LimsDriverServer".
  3. Открой свежий лог в C:\temp\: Приходит ли символ <ENQ>? Если нет — прибор физически не посылает сигнал (в меню прибора выключен автоэкспорт).
  4. Посмотри строку Order: Есть ли штрихкод в поле O|1|...? Если там пусто или O|1|||... — прибор не прочитал штрихкод, и драйвер не знает, к какому пациенту привязать тест.
  5. Проверь строку ошибки: Если видишь Unknown test code XXX — открой файл VMOM.xml и пропиши алиас для этого теста.
2
Симптом: Не печатаются бланки результатов / сбой Сервера Отчетов

Пошаговый алгоритм проверки:

  1. Проверь статус исследования в ЛИС: Бланк печатается только если все обязательные тесты переведены в статус Утвержден / Одобрен врачом КЛД.
  2. Очисти спулер печати Windows: Выполни команды в cmd:
    net stop spooler del /Q /F /S "%systemroot%\System32\Spool\Printers\*.*" net start spooler
  3. Перезапусти службу Сервера Отчетов: net stop !RS_Backend && net start !RS_Backend.

📋 Как оформить грамотный баг-репорт по прибору разработчикам
В тикете очереди Drivers всегда прикладывай:
  1. Полный файл лога драйвера за день (из C:\temp\).
  2. Файл маппинга (.VMOM.xml или .test.map).
  3. Точный штрихкод пробы и фото экрана анализатора с результатами теста.
  4. Модель анализатора, версию прошивки и версию сборки драйвера из первой строчки лога.
